# PII 탐지·마스킹 계층

## 목적

피해 상황에는 전화번호, 이메일, 주민등록번호, 계좌번호처럼 민감한 값이
포함될 수 있다. 분석기가 원문 전체를 직접 처리하지 않도록 API 입구에서
정규식 기반 마스킹을 수행한다.

```text
사용자 입력
→ 입력 길이·공백 검증
→ PII 탐지·마스킹
→ 마스킹 통계 기록
→ 규칙 기반 안전 분석
→ 기존 AnalyzeResponse 반환
```

## 현재 탐지 범위

- 주민등록번호 형식
- 이메일
- 국내 휴대전화·지역 전화번호
- 16자리 결제 카드번호
- `계좌번호`, `통장번호`, `송금 계좌` 문맥 뒤의 숫자
- `인증번호`, `OTP`, `보안코드` 문맥 뒤의 4~8자리 숫자

## 오탐 방지 원칙

- `112`, `118`, `1366` 같은 단축번호는 전화번호로 마스킹하지 않는다.
- 날짜와 일반 숫자는 그대로 유지한다.
- 계좌번호와 인증번호는 관련 문맥이 있을 때만 마스킹한다.
- 사람 이름이나 일반 주소는 현재 규칙만으로 정확히 식별하기 어려워
  자동 마스킹 범위에 포함하지 않는다.

## 데이터 처리 원칙

- `PIIRedactionResult`는 마스킹된 텍스트와 유형별 개수만 보관한다.
- 탐지된 실제 값과 요청 원문을 애플리케이션 로그에 남기지 않는다.
- API 응답에는 실제 민감정보 값을 포함하지 않는다.
- 로그에는 총 탐지 개수와 카테고리 식별자만 기록한다.
- 요청 처리 중 메모리에 존재하는 원문을 영구 저장하지 않는다.

## 한계

- 정규식 기반이므로 새로운 표기법이나 의도적으로 분리된 문자열을
  놓칠 수 있다.
- 이름·주소·조직 내부 식별번호를 포괄적으로 탐지하지 않는다.
- HTTPS, 접근제어, 데이터베이스 암호화를 대신하지 않는다.
- 실제 운영에서는 보안 로그 검토와 데이터 보존 정책이 별도로 필요하다.

## 검증

```bash
cd backend
python -m pytest
```
